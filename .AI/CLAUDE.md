# CLAUDE.md

@AGENTS.md

아래는 Claude Code 전용 규칙이다. 공통 규칙과 충돌하면 AGENTS.md가 우선한다.

## 작업 흐름

1. 새 기능은 plan mode로 시작한다. 계획에는 변경할 파일 목록, 데이터 흐름, 테스트 계획을 포함한다. 승인 전에는 파일을 수정하지 않는다.
2. 구현이 끝나면 리뷰 가이드를 남긴다.
   - 읽는 순서 (어느 파일부터 보면 흐름이 이해되는지)
   - 핵심 로직 위치 (`file:line`)
   - 다룬 엣지 케이스와 다루지 않은 엣지 케이스
3. `packages/merkle` 작업 시에는 근거가 된 RFC 9162 섹션 번호를 함께 적는다.
4. 사람이 리뷰 중 질문하면 코드를 바로 고치지 말고 먼저 답한다. 수정은 요청받았을 때만 한다.

## 서브에이전트

- 코드베이스 탐색, 테스트 실행, 로그 분석에만 사용한다.
- 코드 작성은 메인 세션에서만 한다. 사람이 리뷰할 변경 흐름을 하나로 유지하기 위해서다.

## 금지 명령

다음은 실행하지 않는다. 필요하면 사람에게 요청한다.

- `git push`, `git reset --hard`, `git rebase`, 브랜치 삭제
- `prisma migrate reset`, DB drop, 볼륨 삭제
- `rm -rf`
- `.env*` 파일 읽기·수정 (`.env.example`만 수정 가능)

## 응답 언어

설명과 리뷰 가이드는 한국어로 쓴다. 코드 식별자와 커밋 메시지는 영어로 쓴다.
